# Table, 2026-08-27: both rate-control modes

Six table runs, back to back on one quiet machine: CRF and ABR, each across
the three goal tiers. This file exists because the numbers in README.md had
been re-quoted after the MB_LAMBDA flip without being written down anywhere,
so there was nothing to check them against.

Harness is `scripts/ffboard.py`, both encoders called as libraries inside one
ffmpeg process off the same demuxer. Preset medium, 6-second window, median of
3 samples per cell, 0.35s repeat floor. The pure-C tiers run our scalar path
against the autovec-stripped libx264; the SIMD tier runs both as shipped.

The box was busy with a Photos media-analysis pass when the run was queued, so
the driver waited 63 minutes for it to clear and only started once no process
exceeded 30% CPU and load1 stayed under 3.0 across two consecutive samples.

## ABR, same bitrate on both sides

| goal | configuration | median | max | dVMAF | dSIZE |
|---|---|--:|--:|--:|--:|
| 1 | pure C, single-threaded | 1.02x | 1.20x | -0.27 | +2.8% |
| 2 | pure C, auto-threaded | 1.19x | 1.31x | +0.30 | +2.9% |
| 3 | as-shipped SIMD, auto-threaded | 1.40x | 1.52x | +0.31 | +2.9% |

**Do not read this table as speed.** At a matched bitrate the two encoders do
not do the same work, and the ratio mostly reports which one spent fewer bits.
The rate columns in the raw tables below show how far apart they land:
stefan_cif undershoots its 400 kbps target by 48.8% on our side and 57.4% on
x264's, and on that clip we emit 20.2% more bits and take 1.51x the time. The
dSIZE column carries the same message at the summary level, sitting near 2.9%
across all three tiers against a 1.0% bar. Matching the rate is not the same
as matching the work.

## What changed against the last published table

Goals 1 and 2 reproduce the README's re-quoted CRF values exactly, which
settles the question of whether those numbers were real. Goal 3's median came
in at 0.96x here against 1.01x as published, and its worst clip at 1.14x
against 1.15x.

Taken at face value goal 3 passes all four metrics on this run. It should not
be recorded that way on one draw. The cross-day spread on this machine is
about 0.07 on a median, which is larger than goal 3's entire margin, and that
spread is the machine rather than the encoder. Goal 3 needs the same table
repeated across separate sessions before its status changes.
